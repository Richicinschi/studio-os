# What to pull from each page

| Page | Capture |
|------|---------|
| Homepage | Headline, subheadline, core promise, main call to action, proof claims (numbers, logos, awards), who the copy speaks to |
| Pricing | Each tier with price, what each tier includes, billing choices and any annual discount, free plan or trial length, signs of a custom enterprise tier, per-seat or usage charges, add-on costs |
| Features | Feature groups, headline capabilities, how each is worded, mentions of demos or screenshots |
| About | Founding story, team size, funding, mission line, head office |
| Customers | Named customers and logos, industries, the outcomes the case studies stress |
| Integrations | Total count, the most important named ones, categories |
| Changelog | How often they ship, what the recent releases focus on, hints of where the product is heading |
| Blog index | Posting rate, content types (guides, comparisons, templates), recurring topics |

## Finding pages that hide

If the site map shows no pricing page, test other likely paths such as plans, packages or buy. If there is still none, record "pricing not public", which is itself a finding (usually sales-led).

## Reviews

Look for the competitor on review sites, software directories and launch platforms. For each source capture: average rating, number of reviews, the three themes reviewers praise most, the three they complain about most, and 3 to 5 short quotes with the source named. Reviews that cannot be opened without logging in or that block automated access are skipped and listed as not collected.
