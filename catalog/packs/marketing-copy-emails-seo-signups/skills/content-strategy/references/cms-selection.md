# Choosing a CMS for marketing content

Use this when picking a CMS for a new project or deciding whether a headless setup is worth it.

## What headless means

A headless CMS stores content in a structured backend and serves it through an API. Any front end can read it: a website, an app, an email builder.

## Headless fits when

- Several channels (site, app, email) draw on the same content.
- Developers want full control of the front-end stack.
- Content should be reused in many places.
- The site runs on a modern framework such as Next.js, Remix or Astro.
- Marketers need structured, reusable blocks rather than free-form pages.

## A traditional CMS fits when

- The team is small and has no developer.
- The site is a simple blog or brochure.
- Visual WYSIWYG editing is a firm requirement.
- Budget is tight and WordPress or Webflow already does the job.

## Side by side

| Factor | Headless | Traditional |
|---|---|---|
| Delivery to many channels | Built in | Limited |
| Developer control | Full | Restricted |
| Editing by non-technical staff | Needs setup work | Ready out of the box |
| Time to first launch | Longer | Shorter |
| Content reuse | Native | Copy and paste |
| Where the front end can live | Anywhere | Tied to the platform |

## How the CMS connects to other marketing work

- Programmatic SEO: store repeating records (questions, product comparisons, location pages) as entries of one type, then render a page per entry. See programmatic-seo.
- Copywriting: shape fields after your copy framework (headline, subheadline, proof, call to action) so every page has the same skeleton. See copywriting.
- Site architecture: URL layout, navigation and internal links follow from how content is organized, so design the model and the architecture together. See site-architecture.
- Email: pull case studies, testimonials and posts into email templates so messages stay consistent across web and inbox. See emails.
