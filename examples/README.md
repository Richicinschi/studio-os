# Examples

Stories from the studio, with the names taken out. Each one keeps what happened, what it cost, the rule it produced, and how you can apply it. The module pages point here for their evidence.

| Story | Module | The lesson |
|---|---|---|
| [The green run that would have deleted 190 pages](green-run-that-would-have-deleted.md) | 03 Planning | A run can pass every check and still be wrong; compare the size of the change with what you expected. |
| [Vault before you shorten](vault-before-shortening.md) | 01 Continuity | Free memory by moving text, word for word, to a tagged vault, never by cutting it. |
| [The sweep done by hand](sweep-done-by-hand.md) | 04 Delegation | Long mechanical work goes to a subagent with a self-contained brief, so the main thread keeps moving. |
| [A recorded yes before a merge](grant-before-merge.md) | 06 Git and guardrails | Risky acts wait for an explicit yes for that one act, written down first, and merges keep their full history. |
| [A real address in history](real-address-in-history.md) | 06 Git and guardrails | Deleting a line does not remove it from history, so real network details never go into a commit. |
| [Hooks on a canary first](hooks-canary-rollout.md) | 06 Git and guardrails | Change anything every repository shares on one low-risk repository first, trying every path both ways. |
| [Auditing the studio's own rules](rules-audit.md) | 06 Git and guardrails | Rules drift from what enforces them; a read-only audit now and then finds the gap before a mistake does. |
| [Adopting an outside framework: a review that took no files](outside-framework-review.md) | 05 Skills, 09 Data work | The adoption loop on a real outside framework: a noisy scan, a missed egress, a licence question, and zero files taken. |
| [Scanning a plugin the studio already ran](outside-plugin-scan.md) | 05 Skills, 10 Tools and MCP | A scan said "do not install" over false positives and missed the one real outgoing request; sort the findings, read the code, and decide skill by skill. |
| [The holdout that said no](the-holdout-that-said-no.md) | 12 Experiments and evaluation | A strong result on training data can be a condition of its period; a sealed holdout, opened once, tells, and its "no" is recorded as the result. |
