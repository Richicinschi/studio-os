# Adoption decisions

One row per item, never two items in one row, written by `vet-and-adopt` as soon as the item is applied or staged, with Check "pending"; the Check cell gets the result, and the line that showed it, once the check has run. A skipped item gets a row too, with Check "n/a". The Scan cell holds the scan of the kit's copy and of the installed copy, and whether the scripts are identical: `kit: SAFE 0/100 · installed: SAFE 0/100 · scripts identical`, or `· changed: <names>`, or `· no scripts`. Until the scans after Apply have run it says `installed: pending`; a skipped item has `installed: n/a: not installed`, a folded one `installed: n/a: folded into <file>`, an MCP server or a claude.ai upload `installed: n/a: nothing installed on disk`, and an item with no files `n/a: no files`; a kit item that could not be compared with the kit's record adds `(not compared: <reason>)`. Rows from before v3.4.0 hold one verdict; that is still valid. `drill-to-adopt` reads this file in update mode, so keep the kit version column accurate. The Undo column is the item card's Undo, written for your setup, so anything can be taken out again later. Beside this file, `adoption/installed.json` lists every file and settings key each install wrote, with a SHA-256 of each, written by `node tools/installed.mjs record` from the kit's folder (`vet-and-adopt`, section 5); `node tools/installed.mjs check <setup>` says what changed since, and an undo works from that list.
